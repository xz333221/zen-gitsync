# 我把 32 个项目的 AI 编程，收编进了一块看板

> zen-gitsync 工作台（多项目编排台）实战介绍

## 一个人，32 个项目，和一堆关不掉的终端

我本机现在有 32 个项目在维护：zen-gitsync 自己、todo、home2026、ai-radar、local-cloud-disk、personal-website……

AI 编程工具确实好用，但用久了之后我发现，瓶颈慢慢不在"写代码"上，而在**管理**上：每个项目开一个终端，盯着三四个 AI 来回切窗口；昨晚派出去的任务，今天早上想不起跑没跑完；一个任务卡住了，但它不吭声，你也不知道它是在思考还是已经死了。

我需要的东西很具体：

- 一屏看到**所有项目**的状态，哪个在动、哪个晾着
- 任务派出去之后能**直播**它在干什么，不用点进去翻日志
- 有一个东西能替我把"现在到哪了"总结成一句人话
- 派活的时候只说**人话**，不用先选项目、再选任务、再点执行

这就是我把 zen-gitsync 的工作台做成现在这个样子的原因。它现在的官方名字叫**多项目编排台**，长这样：

![多项目编排台全貌：左项目列表 / 中任务看板 / 右主 Agent 控制台](screenshots/article/14-workbench-overview.png)

（这张是我此刻的实机截图：32 个项目、78 个任务全部完成、0 个在执行。右下角输入框里还放着我刚派出去的一条指令。）

界面上一共三块：

- **左：项目列表** —— 每个项目一行，带图标、当前分支、"x/y 任务完成"的进度。上面有搜索框、`只看有任务`、`隐藏非 Git` 两个过滤。一眼看出哪个项目在动、哪个晾着
- **中：任务看板** —— 待处理 / 进行中 / 已完成三列，卡片上直接显示执行状态，支持看板视图和列表视图切换
- **右：主 Agent 控制台** —— 进度报告 + 指令输入框，你把今天要干的事一句话一句话丢进去

下面按我真实的使用顺序，把这块台子在用的东西过一遍。

## 一、派活：说人话，不用选项目也不用选任务

右下角那个输入框，直接说人话就行：

> 帮我把设置里 AI 模型那块的表单校验补一下

回车。主 Agent 会自己判断这句话该落在哪个项目上、要不要新建任务，然后建好开跑。**你不需要先选项目、再选任务、再点执行。**

当然你也能自己指定：左栏点中哪个项目，指令就默认落在哪个项目。输入框下面一行小字会实时告诉你它准备落在哪：

```
指令会在「zen-gitsync」下新建一个任务；Enter 派发，Shift+Enter 换行
```

输入框旁边两个开关我一直在用：

- **立即执行**（默认勾上）—— 取消勾选就只建任务不跑，等于快速记 TODO。开会时随手记"等下要做的事"，很适合
- **预设提示词（全局 / 本项目）** —— 每个任务前面自动挂一段固定话。全局那段对所有项目生效（我写的是工作区约定、禁止事项、提交规范），每个项目还可以再挂一段自己的（是追加，不是替换）。单次派发可以勾掉它

这一套的意义在于：**派活的成本降到一句话**。以前从"想到一件事"到"它在跑"中间隔着选项目、写标题、选执行器、点执行四步；现在只剩打字。

## 二、看板在直播，不用点进去看

看板中间那列是我最喜欢的部分。一个任务在跑的时候，卡片背面站着一整套事实：

- 用的是哪个 CLI（卡片头上一枚品牌小图标，悬停出全名）
- **已运行**多久
- **工具调用了几次**（悬停看类型分布）
- **最近一次工具调用**是什么
- **最近在想什么**（模型的思考流）
- **最新一句回复**是什么
- 如果它已经安静了一段时间，还会给出**静默时长**

这些不是前端瞎猜的，全部来自执行日志 —— 和右栏那份进度报告读的是同一份数据，5 秒一次跟着真实进程刷新。

于是"我该不该管它"这个判断，不用点开任何东西：一张写着 `已运行 16 分 47 秒 · 工具 20 次 · 思考 Let me edit the probe.` 的卡，看着就是在干活；一张写着自己**静默 4 分**、工具调用停在同一处的卡，就是该看一眼的。

![已完成列的卡片：封面缩略图、用时，以及它跑完时说的最后一句](screenshots/article/02-cards.png)

顺手两个动作：

- 鼠标移到进行中的卡上，会浮出**停止**按钮。以前要杀一个卡死的任务，得点进任务编辑器、滚到最底下、再点停止，现在在板子上就能按
- **已完成**那一列不只显示标题和时间，还会留一句**这条任务最后说的话**（截 100 字，前面带执行器图标）。这个设计有个真实理由：任务跑完停在"要不要我 push？"这种反问上，是最常见的收尾方式。任务在"已完成"列不代表它不需要你 —— 以前只能点进去翻日志才知道它在问什么。带截图附件的任务，卡片顶部还会铺一张封面，点开看大图、方向键翻下一张

## 三、进度报告：不是"派了什么"，而是"现在到哪了"

右栏的指令面板里有一块**进度报告**。它不是把看板上的信息再列一遍，而是让主 Agent 真正去读每个在跑的任务 —— 已运行多久、最近在想什么、工具调用是什么组合、安静了多久、最新输出是什么 —— 然后写一段话告诉你：每件事进行到哪了、看起来卡没卡。

![主 Agent 控制台：进度报告 + 任务事实](screenshots/article/03-orchestrator.png)

每条报告带一根进度条：模型给出它自己对整体进度和每个任务的**估算**，标签直接写"AI 估计"，不装成精确测量。模型不肯给数字的时候那根条就不画，而不是默认画成 0%。

这套报告真正的价值，建立在一个事实上：**绝大多数任务从头到尾不输出一行正文** —— stdout 是空的，你只能看见一个进程还活着。是**思考流**把它们讲清楚的。所以"看起来卡住了"这句判断现在必须带证据 —— 一段静默时长，或者工具调用在原地打转 —— 而不是因为"调用次数高"就下结论。

配套三件事，都是踩坑踩出来的：

**它自己会判断跑完没跑完。** 一条任务静默超过 10 分钟（没正文、没思考、没工具调用），控制台就问主 Agent 一次：读到的事实够了没有，这条是跑完了还是在磨。判"跑完了"就把那张卡从进行中挪到已完成，时间旁边挂一枚「AI 标记完成」，悬停能看到它的理由。证据不足时**它什么都不做**（只记账，再等 10 分钟，最多问 3 次）—— 不动作，好过把正在跑的任务标成完成。它只改记录，从不杀进程：真要终止还是按卡片上那个停止。

**报告只在它还成立的时候占着主位。** 报告是"生成那一刻"的快照，任务跑完之后，卡片上那句"3 个任务进行中"就成了假话。所以这些任务一结束，主位就换掉它，改成说真话的一句：「当前没有任务在执行」或者「正在跑的任务还没有进度报告」。想看旧报告从**历史报告**里点，回来时会打上「已完成」的标记。

**报告是服务端生成的。** 你关掉标签页它照样按点攒，回来接着看。没任务在跑就不落空报告，「立即报告」会直接回你"现在没有任务在跑"，而不是塞一条空的进去浪费一次模型调用；几秒内重复点也不会产生两条一样的。间隔自己挑：5 / 10 / 15 / 30 / 60 分钟，或者关掉。

## 四、看板不止"它说了算"：你能改它的结论

看板的三列是从执行事实推出来的，而有两件事只有你知道：**一件其实是别处干完的**，**一件模型已经不吭声了但你看得见它成了**。

所以待处理和进行中的卡片悬停时会多一个**标记完成**按钮。手工标进"已完成"的卡，那个位置换成**撤销**（一次点击，不弹确认 —— 它就是给"点错了"准备的）；自己跑完的卡两个都不显示。给还在跑的任务手工标完成会先问一句，确认后顺手停掉那次执行 —— 一张卡不能既是已完成又在跑，跨窗口也成立：任务如果活在另一个 `g ui` 窗口里，服务端会直说这个原因，而不是假装成功。

## 五、让任务带着"上一个人踩过的坑"开工

这是我认为整个工作台里最不像功能、但最有用的一件事。

工作台上每个派出去的任务，开工前都会被告知本机有一个**跨轮记忆库** `~/.zen-gitsync/memory/` —— 同一个仓库里，之前那些 agent 留下的经验。

它刻意做成**两级**：

- 只有 `INDEX.md`（每条经验一行、不超过 100 字）会进提示词
- 经验正文放在 `lessons/*.md`，**命中索引行、真的相关时才去读**

不预加载、不读 `archive/`。这个设计就是全部要点所在：把索引整段塞进每一次派发，等于让每个任务都为所有不相干的历史经验付一遍 token。

那个"写"的部分是硬约束的。每个 agent 收工前要自问四个问题 —— 这轮卡了 3 分钟以上或者走了 A→放弃→B 的死路？用错了工具 / 写错了文件？你纠正过它？发现了一条反直觉但验证有效的捷径？任意一条成立，就写**一条**经验，并且**必须**把索引行补上 —— 一条没有索引的经验，就是一条谁也不会发现的记忆。

积累到现在，已经有 60 多条了。`设置 → 记忆库` 能直接翻这个库：范围选择器里是两份全局文件和每个跑过 agent 的仓库（按真实路径分组），点标题展开正文。删一条经验会**连索引行一起删掉** —— 留一行指向不存在的文件，等于给后面的 agent 挖坑。

单个任务可以关掉记忆注入，不过说实话，我关掉一次之后就再没关过。**同一个坑，整个系统只踩一次** —— 这就是这块看板跑得越久越顺手的原因。

## 六、点开卡片：每个任务一个干净进程

点开任意一张卡片，就是任务编辑器 —— 它盖在板子上方，板子在下面继续跑：

![任务执行：对话式执行流 + 执行器 / 复制执行内容 / 执行日志](screenshots/article/05-task-editor.png)

几个我觉得关键的：

**执行器可以选。** Claude Code / OpenCode / Codex 三选一，全局默认在 `设置 → 通用 → 任务执行器` 里，运行按钮旁边那个分裂按钮可以临时切换。**每个任务都是独立拉起的子进程**，跑完即散，上下文和状态不会跨任务累积 —— 这是我敢一次开五个任务的根本原因。

**跑完能接着聊。** 任务进入完成 / 出错 / 已取消之后，输入框会切到续聊模式，发出去的消息会 `--resume` 上一次的会话，新的一轮一轮叠进同一条对话流。但续聊**必须回到起这个会话的执行器** —— Claude 的 `--resume`、OpenCode 的 `--session`、Codex 的 thread id 互不通用。

**附件随便挂。** 图片 / PDF / 文本 / Markdown / CSV / JSON / log，单个到 20 MB；超过 3.5 MB 的图会先在浏览器里压一遍再传，4K 截图也传得上去。它们的绝对路径会拼进提示词，agent 自己去读。4K 的实机截图也传得上去 —— 这篇文章的封面图，当初就是挂在任务附件里给 agent 看的。

**复制执行内容。** 把整条任务（每一轮，不只是屏幕上显示的这些）复制成纯 Markdown：任务和项目的头一行，然后每轮一节，含提示词、思考、工具调用（参数和结果都在围栏里）、模型输出。默认是精简档，旁边的小箭头给全量档。

**三重完成提醒，各有各的开关。** 应用内提示（默认开）、浏览器系统通知（默认关）、提示音（默认开，完成和报错两种音，你自己按停止不响）。三个互相独立，浏览器通知权限只在你打开那个开关的那一刻申请。

## 七、一些让人愿意长期用的细节

**别的窗口在跑什么，这边看得见。** 运行中的任务会落一份 live 记录到磁盘，所以另一个 `g ui` 窗口里跑的任务，在这块看板上照样显示，状态也不打架。反过来，别的窗口的任务你这边停不了 —— 服务端会明确告诉你"这个任务不在当前实例"，而不是甩一句"停止失败"。

**项目行悬停两个按钮：打开文件夹 / 用……打开。** 后者是个菜单：文件管理器、终端、新标签页开一个 `g ui`，以及本机装的各种编辑器和 AI 工具（VS Code、Codex、OpenCode、Kimi Code、ZCode、Claude Code 的普通 / 全权限两种模式）。服务端每 10 分钟探一次这些 CLI，没装的条目置灰并标「未安装」，点一下给你安装引导。

**目录真没了的项目不会消失。** 列表是"最近目录"和"任务记得的路径"的并集，所以删掉的项目仍然占一行，只是那一行给一个红色的**从列表移除**代替打开菜单。确认框会把话说清楚：**不会删任务** —— 哪天你把目录 clone 回来，这一行自己就回来了。

**顶栏常驻 CPU / 内存占用。** 五个任务同时跑的时候，一眼看出是不是把机器榨干了，不用另开任务管理器。

## 写在最后

zen-gitsync 这个名字来自它最早的功能：全局安装之后，终端里输入一个字母 `g`，自动展示 git 状态及 diff，输入提交信息回车，暂存、提交、推送一次完成。但现在的我打开最多的，是这块看板。

它对我而言不是"又一个 AI 编程工具"，而是**管理层的那个工具**：执行器（Claude Code / OpenCode / Codex）负责干活，工作台负责让这些活落在正确的项目上、被看见、被总结、被记住。

安装：

```bash
npm install -g zen-gitsync
```

然后：

```bash
$ g ui     # 打开图形界面，默认就是工作台
$ g        # 或者就在终端里，一个字母提交这次改动
```
